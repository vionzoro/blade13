# BLADE:13 — PRISM BREAK 主题融合设计

日期：2026-08-13  
赛事：js13kGames 2026  
主题：Unicorns and Rainbows  
方向：末日赛博童话 / 棱镜断刃

## 1. 目标

在不破坏 BLADE:13 现有割草战斗、桌面与手机操作、确定性构建和 13KB 提交限制的前提下，让“独角兽与彩虹”成为可见、可操作、可解释的游戏核心，而不是表面换色。

验收时，玩家应当：

- 开局十秒内看到独角和七色棱镜元素；
- 通过击杀、拾取和主动释放体验主题；
- 明确识别 BLACK UNICORN 首领；
- 理解“画面越美丽，战况越危险”的末日反差；
- 在桌面和手机上沿用原有操作，不需要重新学习系统。

## 2. 非目标

- 不新增伙伴 AI、护送任务、关卡地图或第二套资源条；
- 不改变七类敌人的移动、攻击、刷新和数值平衡；
- 不引入图片、字体、音频文件、网络请求或外部依赖；
- 不重做玩家角色骨架、输入系统、升级卡逻辑或存档结构；
- 不以牺牲稳定性、可读性或移动端适配换取更多主题装饰。

## 3. 世界观

霓虹城市曾通过“彩虹网络”输送七色棱镜能源。中央 AI **UNICORN** 失控后，将城市里的机械生命改造成带有发光独角的棱镜兽，并把能源网络变成不断扩张的彩虹灾害。

玩家是最后一名断网猎手，用三把单分子刃切断失控节点。击杀棱镜兽会释放七色碎片；吸收这些能量既能强化玩家，也会令城市的颜色和危险程度同时上升。

标题使用 **BLADE:13 — PRISM BREAK**。开场目标文案使用 `SEVER THE UNICORN NETWORK.`，以最少文字交代冲突。

## 4. 核心循环

核心循环为：

`击杀棱镜兽 → 吸收七色碎片 → 选择升级 → 充满棱镜槽 → 手动释放 PRISM BREAK → 用连杀延长爆发`

现有经验、升级、怒气和 Overclock 逻辑保持不变，只重新命名并强化表现：

- 经验晶体变为七色棱镜碎片；
- 怒气槽在界面中表现为棱镜能量槽；
- Overclock 更名为 **PRISM BREAK**；
- 爆发期间，刀光按光谱循环，击杀生成七色粒子和折射冲击环；
- 爆发期间的击杀继续沿用现有延时奖励，不增加新规则；
- 玩家仍需主动选择释放时机，主题表现不会削弱原有决策感。

## 5. 视觉设计

### 5.1 色彩层级

普通状态继续以黑紫城市、冰蓝和品红刀光为主。完整七色光谱只在棱镜碎片、少量城市导光带和 PRISM BREAK 中出现，避免从开局开始就失去视觉层次。

光谱颜色由一份共享颜色表提供，供以下表现复用：

- 经验棱镜；
- 城市断裂导光带；
- PRISM BREAK 刀光；
- 爆发击杀粒子；
- 首领冲击环与主题界面提示。

### 5.2 独角敌人

所有敌人继续使用原有身体剪影和动画，在公共绘制入口增加一枚与朝向一致的发光独角。角的长度和颜色可由敌人类型、精英和首领状态决定：

- 普通敌人：短角，使用其现有家族颜色；
- 精英敌人：更亮的品红描边；
- 首领：更长的黑色棱镜角，带白色高光和暗色光晕；
- 高密度 LOD 模式仍保留角，保证主题在怪群中不会消失。

### 5.3 BLACK UNICORN

现有定时首领沿用重装兽 AI 和数值，只改变表现：

- 生成时显示 `BLACK UNICORN` 警告；
- 独角明显长于普通敌人；
- 入场与震地攻击使用黑色棱镜冲击波和七色边缘；
- 不新增首领技能，以免引入平衡和体积风险。

### 5.4 城市与反馈

程序化城市保留原有夜城结构。部分导光带由单色改为断裂光谱，出现概率维持较低，确保地面信息不会干扰地刺和敌方子弹。

PRISM BREAK 是主题高潮：

- 刀刃与月牙刀光高速循环七色；
- 突进残影出现短暂光谱分层；
- 击杀冲击环呈彩虹折射；
- 现有色差、扭曲和连杀反馈继续增强，形成“越美丽越危险”的反差。

## 6. 代码边界与数据流

改动限制在现有模块内：

- `src/00-core.js`：共享光谱颜色与必要的主题常量；
- `src/20-game.js`：首领警告文案，以及现有击杀状态到光谱表现的最小映射；
- `src/40-render.js`：棱镜碎片、城市导光带、PRISM BREAK 刀光、界面和开场文案；
- `src/45-art.js`：公共独角绘制、首领独角和爆发残影；
- `README.md`、`HANDOFF.md`、`提交清单.md`：主题、标题和最终提交说明。

不新增源文件，不改变模块加载顺序。

主题数据流为：

1. 现有击杀逻辑继续更新 `kills` 和怒气，不新增计数器；
2. 渲染层用现有击杀数、对象序号或爆发时间计算光谱索引；
3. 经验对象仍使用现有坐标、价值和速度字段，不形成新的可收集资源；
4. `P.fren > 0` 继续作为爆发状态的唯一判断；
5. 首领继续使用 `e.boss`，不新增首领类型或状态机；
6. 所有主题表现只读取已有游戏状态，不反向改变战斗数值。

## 7. 体积策略

当前提交 ZIP 为 12,838 字节，距离 13,312 字节硬上限还有 474 字节。主题版目标为不超过 13,100 字节，至少保留 212 字节余量。

实现顺序按照“辨识度 / 字节成本”排序：

1. 标题、开场目标和 PRISM BREAK 文案；
2. 公共独角与 BLACK UNICORN 表现；
3. 棱镜碎片与爆发光谱；
4. 少量城市彩虹导光带；
5. 文档更新。

每完成一组运行一次确定性构建并记录 ZIP 大小。若超过目标，按以下顺序缩减：

1. 合并重复颜色和路径表达式；
2. 缩短非必要界面文案；
3. 减少城市装饰变体；
4. 简化首领额外光效。

不得通过移除输入支持、测试、防护检查、敌人行为或核心战斗反馈来换取体积。

## 8. 异常与降级

- 主题逻辑不创建新的失败状态；任何光谱索引都通过取模约束在颜色表范围内；
- 高敌人数时沿用现有 LOD，保留独角剪影但省略昂贵光晕；
- 自适应质量继续关闭较重的扭曲和色差，基础彩虹颜色仍应可见；
- 如果构建超过 13,312 字节，则构建视为失败，不生成可提交版本；
- 如果任何自动测试或压缩包冒烟测试失败，保留最近一个通过验证的构建，不上传失败版本。

## 9. 验证计划

自动验证：

- `npm run verify` 全部通过；
- 确定性构建两次产生相同哈希；
- Roadroller 压缩后的 `index.html` 能正常启动；
- release guard 确认无外部请求、受限名称或意外资产；
- 现有 runner、bot、render、portrait 和性能探针继续通过。

人工验收：

- 桌面键盘完成移动、自动攻击、Blink、PRISM BREAK 和升级选择；
- 手机竖屏完成拖动、点击 Blink 和爆发按钮操作；
- 开局十秒内同时看到发光独角与彩虹元素；
- 触发一次 PRISM BREAK，确认刀光、残影、粒子和冲击环层级清楚；
- 等待 BLACK UNICORN 出现，确认名称、角和攻击预警可辨；
- 地刺、敌方子弹、经验棱镜在颜色和形状上仍能区分；
- 最终 ZIP 只包含根目录 `index.html`，且不超过 13,100 字节目标。

## 10. 完成定义

当且仅当主题表现、桌面与手机操作、完整自动测试、人工视觉验收、确定性构建、风险扫描和 ZIP 体积目标全部通过，主题融合才算完成。最终上传与对外发布仍需在赛事提交表单开放后单独确认。
